# Документы студенческого репозитория

Раньше в этом файле лежала инструкция для студентов, которая целиком
копировалась в `README.md` шаблона. Теперь документов три, и каждый
хранится отдельным файлом-источником:

| Источник | Куда попадает в шаблоне | Кто редактирует |
|---|---|---|
| `admin/template-README.md` | `README.md` | заготовка; заполняет студент |
| `admin/template-TASK.md` | `TASK.md` | преподаватель |
| `admin/template-GUIDE.md` | `GUIDE.md` | преподаватель |

## Что в каждом файле

**`README.md`** — титульная страница репозитория студента: чей репозиторий,
ссылки на остальные документы, команды запуска и **описание варианта**
(свойства языка, типы, операции, функции). Заготовку с плейсхолдерами
заполняет студент. На этот файл опирается и преподаватель, и ИИ-ревью.

**`TASK.md`** — требования практикума: последовательность из пяти
лабораторных работ, структура отчёта, требования к разрабатываемому языку.
**Собирается автоматически** из партиалов `docs/_partials/` командой
`python3 tools/build-docs.py`; править `admin/template-TASK.md` руками
нельзя — правки затрёт следующая сборка. Таблицы вариантов в нём нет:
конкретный вариант студент находит на [сайте курса](https://rserdyukov.github.io/yapis-2026/labs/variants/)
и выписывает в свой `README.md`.

**`GUIDE.md`** — как работать: ветки `task<номер>`, Pull Request, правила
ИИ-ревью, локальная проверка, базовые команды git.

## Порядок внесения изменений

Правки вносятся **только в этом репозитории**. Шаблон и репозитории
студентов — производные, руками их менять не нужно.

```
yapis-2026  ──sync-template──>  шаблон  ──sync-workflow──>  репозитории студентов
```

```bash
cd admin

# 1. Проверить, что ничего не сломано (53 теста, без обращения к API)
bash ../.github/review/tests/run-tests.sh

# 2. Раскатать в шаблон
./manage.sh sync-template

# 3. Раскатать по существующим репозиториям студентов (создаёт PR в каждом)
./manage.sh sync-workflow
```

Шаг 2 отделён от шага 3 намеренно: между ними шаблон можно просмотреть
глазами, а новые репозитории студентов сразу создаются из свежего шаблона.

### Что именно копируется

Состав задан в [`template-manifest.txt`](template-manifest.txt) — это
единственное место, где он описан. Оттуда его читают обе команды и тесты,
так что списки не могут разъехаться.

| Что | В шаблон | Студентам |
|---|---|---|
| `TASK.md`, `GUIDE.md` | да | да |
| `review-local.sh` | да | да |
| `guard-main.yml` | да | да |
| `README.md` | да (заготовка) | **нет** |
| `.github/review/**` (движок ревью) | нет | нет |

Движок ревью студентам не раздаётся: ИИ-ревью выполняется централизованно
в приватном репозитории преподавателя (`./manage.sh sync-reviewer`). Так
ключ модели не попадает к студентам, а промпты нельзя подменить в своей
ветке. Для локальной проверки `review-local.sh` сам скачивает промпты и
проверки из публичного репозитория курса.

Три пометки в манифесте управляют исключениями:

- `!EXCLUDE` — не попадает в целевой репозиторий вообще. Так помечены
  тесты инфраструктуры: это инструмент преподавателя.
- `!STUDENT_KEEP` — есть в шаблоне, но `sync-workflow` не перезаписывает
  это у студентов. Так помечен `README.md`: в шаблоне там заготовка, а у
  студента — его собственное описание варианта.
- `!STUDENT_REMOVE` — наоборот, активно удаляется из репозиториев
  студентов. Так помечены остатки прежней схемы, когда ревью запускалось
  прямо у студента (`ai-review.yml`, `.github/review/**`).

### Разница между sync-template и sync-workflow

| | `sync-template` | `sync-workflow` |
|---|---|---|
| Куда | В шаблон | В репозитории студентов |
| Откуда | Из этого репозитория | Из шаблона |
| Как | Коммит прямо в `main` | Pull Request в каждом репозитории |
| `README.md` студента | Перезаписывает (в шаблоне это заготовка) | **Не трогает** |

Обе команды идемпотентны: если изменений нет, они ничего не делают.
`sync-workflow` при повторном запуске обновляет уже открытый PR, а не
плодит новые.

> Правки `TASK.md` и `GUIDE.md` доезжают до студентов автоматически —
> в отличие от `README.md`, который остаётся их собственным.

## Важно про ссылки в промптах

Промпты ИИ-ревью ссылаются на `TASK.md` и `README.md` студента
(см. `COURSE_DOCS` в `.github/review/config.env` и файлы
`.github/review/tasks/*/prompt.md`). Если переименуете документы в шаблоне —
обновите и эти ссылки, иначе модель будет искать несуществующие файлы.
