# Бриф автора статьи цифрового сада

Репозиторий: /Users/serdyukov/projects/yapis-2026 — сайт университетского курса
«Языковые процессоры интеллектуальных систем» (MkDocs Material, русский язык).
Читатель — студент 3–4 курса, пишущий собственный компилятор (ANTLR, генерация
кода в JVM/CIL/LLVM/WASM/CPython). Раздел «Цифровой сад» — статьи об идеях,
реализованных в языках программирования: зачем идея появилась, как она устроена,
что стоит, что из неё следует для автора языка.

## Что ты пишешь

Только файлы, названные в задании:
- `docs/garden/<slug>.md` — статья;
- `docs/garden/src/<slug>/…` — исходники примеров (каждый пример — отдельный файл,
  который реально компилируется/запускается как есть).
Никакие другие файлы не трогай (ни mkdocs.yml, ни генераторы, ни YAML данных,
ни docs/garden/index.md) — параллельно работают другие авторы.

## Формат статьи

Front matter (строго так, YAML):

```yaml
---
publish: true
title: "Rust: владение и заимствование"
description: "Одна фраза — тезис статьи."
languages: [rust]            # id карточек каталога (docs/languages/_data/languages/<id>.yaml)
concepts: [memory.transfer, memory.management]   # id понятий из docs/languages/_data/ontology.yaml
---
```

`languages` и `concepts` — только существующие id (проверь по файлам). Генератор
построит обратные ссылки: на карточке языка и у понятия в словаре появится
ссылка на статью. Бери 3–7 понятий, которые статья действительно объясняет.

Объём — подробный разбор, 4–6 экранов (примерно 1500–2500 слов текста без кода).
Структура (заголовки второго уровня, можно переименовывать по смыслу):

1. `# Заголовок` (= title), под ним одна строка-тезис курсивом.
2. `## Проблема` — какую боль идея снимает; как её решали до и в других языках.
3. `## Идея` — суть в 1–2 абзацах, затем устройство с примерами кода.
4. `## Как это работает` / разбор примеров — 3–5 примеров с результатом запуска.
5. `## Цена` — компромиссы, критика, где идея мешает.
6. `## Сравнение` — как то же решают 2–3 других языка (коротко, с кодом или таблицей).
7. `## Что взять в свой язык` — практические выводы для студента, пишущего
   компилятор (что это значит для грамматики, семантического анализа, генерации кода).
8. `## Упражнение` — 1–2 задания (предсказать/изменить/реализовать).
9. `## Источники` — список: первичные источники (спецификации, статьи авторов языка).

## Примеры кода

- Каждый пример лежит в `docs/garden/src/<slug>/имя.ext` и включается в статью
  через pymdownx.snippets (путь относительно docs/garden):

  ````markdown
  ```rust title="borrow.rs"
  --8<-- "src/rust-ownership/borrow.rs"
  ```
  ````

  Можно включать фрагмент файла секциями: в файле `// --8<-- [start:name]` …
  `// --8<-- [end:name]` (для Lua/SQL/Haskell/Erlang — соответствующий комментарий:
  `-- --8<-- [start:name]`, `% --8<-- [start:name]`, `\ --8<-- [start:name]` для Forth,
  `⍝ --8<-- [start:name]` для APL, `" --8<-- [start:name]"` для Smalltalk — строка-комментарий)
  и `--8<-- "src/<slug>/file.rs:name"`. Имя секции `[a-z][-_0-9a-z]*`.
- После кода — блок результата:

  ````markdown
  ```text title="Вывод"
  ...
  ```
  ````

- Ожидаемую ошибку компиляции показывай дословно (ключевые строки диагностики).
- Под каждым примером (или в начале раздела) отметь статус проверки ровно одной из форм:
  - `**Проверено:** rustc 1.98.1, macOS.` — если ты действительно запустил;
  - `**Не запускалось:** вывод по документации <ссылка>.` — если компилятора нет.
  Никогда не выдавай ожидаемый вывод за полученный.
- Установленные инструменты (запускать можно только их, ничего не устанавливай):
  rustc/cargo 1.98.1, node 22.23.3, lua 5.5.1, sqlite3 3.51.0, python3 3.14.7.
  Нет: go, zig, erlang, gforth, apl, smalltalk, ghc. Для этих языков пиши код
  максимально консервативно (по спецификации/документации), помечай «Не запускалось»
  со ссылкой на раздел документации, из которого следует результат.
- В `docs/garden/src/<slug>/README.md` не нужно. Но создай файл
  `docs/garden/src/<slug>/run.sh` — bash-скрипт, который из этой папки запускает
  все примеры и печатает вывод (для непроверенных — те же команды, как их запускать).
  Первая строка `#!/usr/bin/env bash`, `set -u`. Скрипт не должен ничего устанавливать.

## Стиль

- Русский язык, ясный, без канцелярита и восклицаний. Термины при первом упоминании:
  «заимствование (borrowing)». Код и идентификаторы — в `обратных кавычках`.
- Никаких необоснованных утверждений о производительности/популярности. Исторические
  факты — только с источником. Не выдумывай цитаты; прямая цитата допустима только
  дословная из источника с ссылкой.
- Честно про ограничения: если идея спорная — изложи критику.
- Ссылки внутри сайта — относительные Markdown-ссылки на .md-файлы:
  карточка языка `../languages/rust.md`, понятие в словаре
  `../languages/glossary.md#memory-transfer` (slug понятия = id с заменой `.` и `_` на `-`;
  проверь поле `slug` в ontology.yaml), люди `../languages/people.md#pike`,
  источники `../languages/sources.md#hopl-lua`, другие статьи сада `other-slug.md`.
  Существующие id людей и источников — в docs/languages/_data/people.yaml и
  sources.yaml. Можно ссылаться на различающие примеры
  `../concepts/examples/index.md#sql` и лекции `../lectures/html/<slug>.html`
  (список в docs/lectures/index.md).
- Внешние ссылки — только на официальные спецификации/документацию/статьи, в которых
  ты уверен (URL должен существовать). Можно проверить curl'ом (`curl -sI -L URL`).
- Admonitions MkDocs допустимы: `!!! note "…"`, `!!! warning "…"`, `??? question "Ответ"`
  (раскрываемый ответ к упражнению).
- Заголовки таблиц и списки — обычный Markdown. Не используй HTML без нужды.

## Проверка перед сдачей

1. Все примеры, для которых есть инструмент, запущены, вывод совпадает с текстом.
2. `bash docs/garden/src/<slug>/run.sh` отрабатывает (для запускаемых языков).
3. Сборка сайта — не обязательна (её сделает координатор), но проверь, что все пути
   в `--8<--` указывают на существующие файлы и секции.
