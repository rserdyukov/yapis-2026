# Lua: метатаблицы, язык как конструктор

*Механизмы, а не политика: ядро языка знает только таблицы и умеет спросить программиста, что делать, когда операция не определена.*

## Проблема

Язык расширения (extension language) встраивается в чужую программу: игру,
текстовый редактор, сетевое устройство. Авторы Lua описывают его как
«расширяемый язык расширения»: хост-программа на C вызывает Lua для
конфигурации и сценариев, а Lua вызывает функции хоста
([HOPL III, «The Evolution of Lua»](../languages/sources.md#hopl-lua)).
Отсюда два противоречивых требования. Интерпретатор должен быть маленьким
и простым, потому что его вкладывают в каждую программу. Но пользователи
хотят объекты, классы, наследование, перегрузку операторов, а объекты
хоста (окно, сокет, игровой персонаж) должны выглядеть в Lua как «родные»
значения.

Обычный путь — встроить в язык конкретную объектную модель: классы в
C++ и Java, классы с метаклассами в Smalltalk и Python. Каждое такое
решение фиксирует политику: как устроено наследование (одиночное,
множественное, примеси), где хранятся методы, что значит `==`.
[Роберту Иерузалимски](../languages/people.md#ierusalimschy) и соавторы
пишут, что в начале 1990-х на них давили пользователи, требуя
объектно-ориентированных средств, но они не захотели закреплять в Lua одну
парадигму: объекты и классы можно построить из таблиц, раз функции —
значения первого класса. Вместо модели они в Lua 2.1 (февраль 1995)
добавили механизм «расширяемой семантики» и с тех пор следуют принципу
«mechanisms, not policy» ([hopl-lua](../languages/sources.md#hopl-lua),
§5.2 и §6.8).

## Идея

В Lua одна составная структура данных — таблица, ассоциативный массив с
ключами любого типа. Массивы, записи, модули, множества и объекты — всё
таблицы. К таблице можно прикрепить *метатаблицу* (metatable) — обычную
таблицу, поля которой с именами вида `__add`, `__index`, `__call` задают
поведение значения в ситуациях, где встроенная семантика не знает, что
делать. Функция в таком поле называется *метаметодом* (metamethod).

Ключевое слово в описании — «когда не знает». Руководство формулирует
правило для сложения так: если хотя бы один операнд `+` не число, Lua
ищет поле `__add` в метатаблице сначала первого, потом второго операнда и
вызывает найденную функцию; если её нет — ошибка
([Lua 5.4 manual §2.4](https://www.lua.org/manual/5.4/manual.html#2.4)).
Для индексирования `t[k]` метаметод `__index` вызывается, только если
ключа `k` в таблице нет. Историческое имя механизма это подчёркивает: в
Lua 2.1 он назывался *fallbacks* — «запасной ход» на случай, когда Lua не
знает, как продолжать; в Lua 3.0 его заменили tag methods, в Lua 5.0 —
метатаблицы ([hopl-lua](../languages/sources.md#hopl-lua), §6.8).

Основные события:

| Поле | Когда срабатывает |
|---|---|
| `__index` | чтение отсутствующего ключа `t[k]`; значение — таблица (искать в ней) или функция `(t, k)` |
| `__newindex` | запись в отсутствующий ключ `t[k] = v` |
| `__call` | вызов не-функции `t(...)` |
| `__add`, `__sub`, `__concat`, … | арифметика с не-числами, конкатенация с операндом, который не строка и не число |
| `__eq`, `__lt`, `__le` | сравнение двух таблиц (для `__eq` — если они не один и тот же объект) |
| `__len` | оператор длины `#t` |
| `__tostring`, `__name` | используются библиотечной функцией `tostring` |
| `__close` | выход из области видимости переменной `<close>` (Lua 5.4+) |
| `__gc`, `__mode` | финализатор и слабые ссылки для сборщика мусора |

К механизму прилагаются две вещи. Первая — «сырые» функции `rawget`,
`rawset`, `rawequal`, `rawlen`: они выполняют операцию без обращения к
метатаблице и нужны, чтобы метаметод мог добраться до настоящих данных,
не зациклившись. Вторая — синтаксический сахар `:`. Запись
`function A:m(x)` означает `function A.m(self, x)`, а вызов `obj:m(x)` —
`obj.m(obj, x)`, причём `obj` вычисляется один раз
([§3.4.10](https://www.lua.org/manual/5.4/manual.html#3.4.10),
[§3.4.11](https://www.lua.org/manual/5.4/manual.html#3.4.11)). Ни
`self`, ни «метода» в семантике нет — это обычный параметр и обычное поле.

**Проверено:** все примеры на Lua запускались интерпретатором Lua 5.5.1
(PUC-Rio), macOS. Используемые возможности описаны в руководстве Lua 5.4 и
в 5.5 не менялись; [карточка Lua](../languages/lua.md) описывает срез 5.4.

## Как это работает

### Класс и конструктор

Класс — таблица с методами. Экземпляр — пустая таблица, у которой
метатаблица — сам класс, а поле `__index` класса указывает на него же.
Когда в экземпляре нет поля `deposit`, чтение `a.deposit` переходит по
`__index` в `Account`.

```lua title="class.lua"
--8<-- "src/lua-metatables/class.lua:class"
```

```text title="Вывод"
Ann: 150
nil	true
```

`rawget(a, "deposit")` возвращает `nil`: метода в объекте нет, он найден
делегированием. Именно так выглядит одиночная диспетчеризация в Lua:
выбор функции зависит только от получателя, а `a:deposit(50)` — просто
поиск поля плюс вызов с `a` первым аргументом.

### Наследование цепочкой метатаблиц

Чтобы `Savings` унаследовал от `Account`, достаточно дать самой таблице
`Savings` метатаблицу с `__index = Account`. Поиск идёт
`s → Savings → Account`: руководство прямо говорит, что если `__index` —
таблица, то индексирование её «обычное, не сырое» и может вызвать
следующий `__index`.

```lua title="class.lua"
--8<-- "src/lua-metatables/class.lua:inherit"
```

```text title="Вывод"
[savings] Bob: 300.0
nil	nil	true
true	true
```

Вызов «родительского» метода — явное `Account.report(self)`: ключевого
слова `super` нет, есть только таблицы. `300.0` вместо `300` — не ошибка
механизма: `200 * 0.5` даёт вещественное число, и баланс становится
float (в Lua 5.3+ у number два подтипа).

### Перегрузка операторов

Операторы задаются метаметодами. Это не перегрузка функций по сигнатуре —
в Lua её нет ([subprograms.overloading](../languages/glossary.md#subprograms-overloading)
для Lua — «нет»): у имени одна функция, а метаметод сам разбирает типы
аргументов в теле.

```lua title="vector.lua"
--8<-- "src/lua-metatables/vector.lua"
```

```text title="Вывод"
(4, 6)	(11, 12)	(11, 12)
true	false
true	false	2
false	vector.lua:23: attempt to concatenate a table value (upvalue 'p')
false	vector.lua:24: attempt to compare two table values
```

Что видно из вывода:

- `10 + p` работает, потому что Lua ищет `__add` и у второго операнда;
  порядок аргументов метаметод получает исходный, поэтому ему пришлось
  менять их местами.
- `==` с `__eq` сравнивает по значению, `rawequal` — по идентичности.
- `__le` не выводится из `__lt`: в Lua 5.4 эту замену убрали, и `p <= q`
  без `__le` — ошибка. Каждое событие — отдельный крючок, никакой
  «алгебры» между ними язык не достраивает.

### Прокси, значения по умолчанию, только для чтения

Раз `__index` и `__newindex` срабатывают только на *отсутствующие* ключи,
прокси делают пустым: тогда через метаметоды проходит каждое обращение.

```lua title="proxy.lua"
--8<-- "src/lua-metatables/proxy.lua:proxy"
```

```text title="Вывод"
get cfg.port
set cfg.port = 81
get cfg.port
81	nil
```

Значение по умолчанию — `__index`-функция, возвращающая константу; таблица
только для чтения — прокси, у которого `__newindex` вызывает `error`:

```lua title="proxy.lua"
--8<-- "src/lua-metatables/proxy.lua:defaults"

--8<-- "src/lua-metatables/proxy.lua:readonly"
```

```text title="Вывод"
3	1	0	nil
Tue	3
false	proxy.lua:44: attempt to modify read-only field 4
Thu
```

Последняя строка — честное напоминание: защита «только для чтения»
держится на соглашении. `rawset` обходит метаметоды, и запрет исчезает.
Это не баг, а следствие принципа: язык дал механизм, строгость политики
решает автор библиотеки (и среда, которая может убрать `rawset` из
окружения недоверенного кода).

### Мемоизация и функторы

`__index`-функция может вычислить значение и сохранить его `rawset`,
после чего следующий доступ к ключу метаметод уже не вызывает. `__call`
делает таблицу вызываемой: этим часто оформляют «конструктор» `Class(...)`
и объекты-функции.

```lua title="memo.lua"
--8<-- "src/lua-metatables/memo.lua:memo"

--8<-- "src/lua-metatables/memo.lua:call"
```

```text title="Вывод"
23416728348467685	79
23416728348467685	79
11	16	16	table
```

`fib[80]` вызвал `__index` 79 раз (для ключей 2…80), повторный доступ —
ни разу. `c` остаётся таблицей (`type(c) == "table"`), но ведёт себя как
функция: это утиная типизация на уровне операций — допустимость `c()`
определяется наличием метаметода во время выполнения, а не типом.

### Детерминированная очистка: `__close`

С Lua 5.4 локальная переменная с атрибутом `<close>` при выходе из блока
вызывает метаметод `__close` своего значения — при обычном выходе,
`break`, `return` или ошибке
([§3.3.8](https://www.lua.org/manual/5.4/manual.html#3.3.8)). Так же
через метатаблицу подключён и финализатор `__gc`, но его вызывает сборщик
мусора в неопределённый момент.

```lua title="close.lua"
--8<-- "src/lua-metatables/close.lua"
```

```text title="Вывод"
open A
open B
work
close B
close A
open F
close F after error: boom
false	boom
gc finalizer
end
```

Даже новая управляющая конструкция языка (аналог `using`/`with`) не
получила собственного протокола: она спрашивает у значения метатаблицу,
как и `+`.

## Цена

**Нет одной объектной системы.** Авторы сами пишут, что пользователи
предложили и реализовали несколько объектных моделей и что это частая тема
обсуждений в рассылке; они считают это здоровым
([hopl-lua](../languages/sources.md#hopl-lua), §5.2). Обратная сторона —
библиотеки из разных источников по-разному понимают «класс», «конструктор»
(`new`, `Class(...)`, `Class:create`), вызов родителя и проверку
принадлежности (`isinstance` приходится писать самим). Код, совмещающий
две такие библиотеки, склеивает две модели.

**Политика всё равно понадобилась.** Для модулей авторы признают, что
«вопреки принципу механизмов, а не политики» в Lua 5.1 определили набор
политик написания модулей и загрузки пакетов
([hopl-lua](../languages/sources.md#hopl-lua), §5.5). Где нужна
совместимость экосистемы, соглашение, закреплённое в стандартной
библиотеке, выигрывает у свободы.

**Стоимость поиска.** Каждый уровень наследования — ещё одно промахнувшееся
чтение таблицы и переход по `__index`; `__index`-функция — ещё и вызов.
Насколько это заметно, зависит от реализации и программы; частая практика —
копировать методы родителя в класс-потомок при его создании, меняя
позднее связывание на скорость и память. Эталонная реализация ограничивает
длину цепочки: `setmetatable(t, {__index = t})` даёт ошибку
`'__index' chain too long; possible loop`, а не зацикливание.

**Отладка и неожиданности.** Операция `a.b` может выполнить произвольный
код; сообщение об ошибке указывает на место использования, а не на
метатаблицу, где задана семантика. Некоторые метаметоды работают только
для таблиц и userdata: у чисел и строк одна метатаблица на тип, и из Lua
её не поменять без библиотеки `debug`
([§2.4](https://www.lua.org/manual/5.4/manual.html#2.4)). Правила «когда
вызывается метаметод» различаются по событиям (`__eq` — только если
операнды не идентичны, `__index` — только для отсутствующих ключей), и их
приходится знать.

**Нет статической проверки.** Инструменты, которые хотят понимать классы
в Lua (автодополнение, анализаторы), вынуждены угадывать, какую из
пользовательских моделей применяет код, или полагаться на аннотации в
комментариях.

## Сравнение

**JavaScript** выбрал похожую основу — объекты-словари и прототипное
делегирование, пришедшее из Self (авторы Lua сами проводят эту параллель,
[hopl-lua](../languages/sources.md#hopl-lua), §6.8). Разница в деталях:
цепочка `[[Prototype]]` — встроенная часть объекта, а не одно из событий
метатаблицы; `Proxy` перехватывает *каждое* обращение, а не только промах;
операторы переопределить нельзя — `+` лишь приводит объект к примитиву
через `valueOf`/`toString`.

```js title="compare.js"
--8<-- "src/lua-metatables/compare.js"
```

**Python** выражает то же специальными методами класса (`__add__`,
`__eq__`, `__getattr__`, `__call__`). Политика здесь закреплена: есть
классы, `super()`, MRO для множественного наследования. Показательная
деталь — специальные методы для операторов ищутся в типе, а не в
экземпляре ([Data model, §3.3.13 Special method lookup](https://docs.python.org/3/reference/datamodel.html#special-method-lookup)),
так что присваивание `p.__add__ = ...` на `+` не влияет. `__getattr__`
вызывается только для отсутствующих атрибутов — прямой аналог
`__index`-функции.

```python title="compare.py"
--8<-- "src/lua-metatables/compare.py"
```

```text title="Вывод (node compare.js, затем python3 compare.py)"

get port
set port = 81
81
43 (1, 2)
(4, 6) True False
5 0
(1, 2)
```

**Проверено:** node 22.23.3 и python3 3.14.7, macOS.

**Smalltalk и Ruby** идут дальше в ту же сторону, но с политикой внутри:
любое действие — посылка сообщения, у объекта есть класс, а неизвестное
сообщение приводит к вызову `doesNotUnderstand:` (Smalltalk) или
`method_missing` (Ruby) — это тот же «запасной ход», что `__index`, только
встроенный в фиксированную классовую модель.

| | Lua | JavaScript | Python |
|---|---|---|---|
| Где хранится поведение | метатаблица значения | цепочка прототипов, `Proxy` | тип (класс) |
| Перехват чтения | `__index` при промахе | `Proxy.get` всегда | `__getattr__` при промахе, `__getattribute__` всегда |
| Перегрузка операторов | да, метаметоды | нет | да, dunder-методы |
| Встроенные классы | нет | `class` — сахар над прототипами | да |

## Что взять в свой язык

1. **Маленькое ядро с точками расширения дешевле большого ядра.** Если
   ваш язык предназначен для встраивания или DSL, подумайте, какие
   операции пользователь захочет переопределить, и сделайте для них
   крючки, а не готовые конструкции. Одна структура данных и таблица
   обработчиков событий заменяют классы, свойства, прокси и перегрузку.
2. **Диспетчеризация «на промахе» проста в реализации.** В интерпретаторе
   или сгенерированном коде каждая операция получает быстрый путь
   (встроенный тип) и медленный (поиск обработчика). Модель на самом Lua:

    ```lua title="dispatch.lua"
    --8<-- "src/lua-metatables/dispatch.lua:model"
    ```

    ```text title="Вывод"
    3	V+3	true
    hi	true	nil
    false	attempt to perform arithmetic on a table value
    ```

    В кодогенерации для JVM/CIL это ветвление перед операцией: проверка
    тега значения, при неудаче — вызов функции среды выполнения
    `rt_add(a, b)`, которая ищет обработчик. Для LLVM/WASM — то же самое
    явным `br` на медленный путь.
3. **Нужны «сырые» операции.** Без `rawget`/`rawset` обработчик не
   сможет обратиться к данным, не вызвав сам себя. Предусмотрите их в
   стандартной библиотеке сразу.
4. **Решите, где хранится поведение.** Метатаблица у значения (Lua) даёт
   гибкость, поведение в типе (Python) позволяет семантическому
   анализатору и оптимизатору заранее знать набор операций. Для
   статически типизированного учебного языка второе обычно удобнее:
   перегрузка операторов разрешается на этапе семантического анализа в
   вызов конкретной функции.
5. **Отделяйте сахар от семантики.** `obj:m(x)` в Lua — чисто
   синтаксическое преобразование в `obj.m(obj, x)` с однократным
   вычислением `obj`. В вашей грамматике такой сахар удобно
   раскрывать при построении AST, чтобы семантический анализ и
   генератор его не видели.

## Упражнение

1. Предскажите вывод, затем проверьте в `lua`:

    ```lua
    local A = {x = 1}
    local B = setmetatable({}, {__index = A})
    local C = setmetatable({}, {__index = B, __newindex = A})
    C.x = 10; C.y = 20
    print(C.x, rawget(C, "x"), A.x, A.y, B.y)
    ```

    ??? question "Ответ"
        `10	nil	10	20	20`. Ключа `x` нет в `C`, поэтому запись уходит
        по `__newindex` в `A` (табличный `__newindex` повторяет
        присваивание в `A`). То же для `y`. Чтение `C.x` идёт по цепочке
        `C → B → A`.

2. Реализуйте множественное наследование: функцию `class(...)`, которая
   принимает несколько родителей и создаёт класс, у которого `__index` —
   функция, ищущая метод в родителях по порядку и кэширующая найденное
   `rawset`. Что будет, если два родителя определяют метод с одним
   именем? Сравните с MRO в Python.
