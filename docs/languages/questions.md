# Вопросы, на которые должна отвечать онтология

Это проверка полезности модели, а не тест с единственным словом-ответом. Для каждого вопроса указаны понятия, содержательный ответ, основания и то, что ещё нельзя получить из структурированных данных. Ответы написаны автором, а не автоматически выведены из матрицы.

Не смешивайте пробел данных, неточное определение и отсутствие нужной оси: для каждого требуется своё исправление. Контекст реализации, профиля и версии нужно проверять на [карточке языка](index.md).

[Словарь и типы связей](glossary.md) · [Различающие примеры](../concepts/examples/index.md)

## Можно ли менять объект через неизменяемое имя? { #q01 }

**Понятия:** [Изменяемость связывания](glossary.md#bindings-mutation), [Права ссылок и ограничения алиасов](glossary.md#memory-reference-permissions), [Передача и разделение владения](glossary.md#memory-transfer)

**Ответ.** Да: JavaScript const запрещает перепривязку, но не запрещает push в массив. Для Pony val утверждение сильнее, чем для box: box запрещает запись через эту ссылку, не обязательно через другие. Нужно сравнивать привязку, объект и права ссылки отдельно.

**Основания и пример.** Карточки JavaScript и Rust описывают привязки; пример Pony сопоставляет box/ref/val.

**Предел текущей модели.** Свойства глубокой и поверхностной изменяемости объекта пока не выделены в отдельную ось; полный поиск по ним невозможен.

**Для реализации языка.** Отделить символ и его переприсваиваемость от типа ссылки и допустимых операций над объектом.

## Отсутствие аннотации означает динамическую типизацию? { #q02 }

**Понятия:** [Введение связывания](glossary.md#bindings-introduction), [Аннотации типов](glossary.md#typing-annotations), [Вывод статических типов](glossary.md#typing-inference), [Проверка типов](glossary.md#typing-checking)

**Ответ.** Нет. Java var и Rust let явно вводят имя, а тип может выводиться статически. Python-аннотация сама по себе не запускает проверку во время исполнения.

**Основания и пример.** Java и Rust показывают статический вывод; Python разделяет language и tooling.

**Предел текущей модели.** Детальные области вывода и роль каждой аннотации пока частично описаны текстом applies_to.

**Для реализации языка.** Разделить разбор деклараций, построение таблицы символов, сбор ограничений типов и их проверку.

## Чем перепривязка отличается от сокрытия имени? { #q03 }

**Понятия:** [Введение связывания](glossary.md#bindings-introduction), [Формы присваивания и связывания](glossary.md#bindings-assignment), [Сокрытие имён](glossary.md#scope-shadowing), [Правило разрешения имён](glossary.md#scope-resolution)

**Ответ.** Перепривязка обновляет обозначаемое существующим именем значение; shadowing вводит новое связывание, скрывающее старое. Повторный let в Rust и повторное присваивание Python нельзя одинаково помечать как shadowing.

**Основания и пример.** Карточки Rust и Python содержат разные значения и пояснения.

**Предел текущей модели.** Время жизни захваченных ячеек и алгоритм хранения окружений не моделируются одной записью scope.

**Для реализации языка.** Назначать идентификатор каждому связыванию, а не использовать текст имени как единственный ключ на всех уровнях.

## Может ли блок иметь границы, но не создавать область имён? { #q04 }

**Понятия:** [Границы синтаксических групп](glossary.md#syntax-blocks), [Конструкции областей видимости](glossary.md#scope-constructs), [Границы операторов и определений](glossary.md#syntax-statement-terminator)

**Ответ.** Да. Python if группирует тело отступами, но не создаёт обычной блочной области локальных переменных. Haskell для ряда групп допускает и layout, и явные скобки.

**Основания и пример.** Карточки Python и Haskell показывают независимость синтаксического и семантического решений.

**Предел текущей модели.** Классификация отдельных конструкций требует контекста; одной метки на язык недостаточно.

**Для реализации языка.** Не создавать scope автоматически на каждый узел AST, названный block.

## Копия ссылки — это передача по ссылке на переменную? { #q05 }

**Понятия:** [Связывание параметров](glossary.md#subprograms-parameter-passing), [Передача и разделение владения](glossary.md#memory-transfer), [Формы присваивания и связывания](glossary.md#bindings-assignment)

**Ответ.** Нет. Java передаёт значение ссылки: изменение объекта может быть видно, но замена значения параметра не меняет переменную вызывающего. C# ref даёт доступ к самой переменной вызывающего.

**Основания и пример.** Карточки Java, C и C# разграничивают значение ссылки и ссылочный параметр.

**Предел текущей модели.** Для copy-out существенны aliasing и порядок обратного копирования; они пока требуют отдельного пояснения.

**Для реализации языка.** Определить, передаётся значение, адрес места хранения или отложенное вычисление; отдельно задать владение.

## Чем checked exception отличается от Result и must-use? { #q06 }

**Понятия:** [Представление и передача ошибок](glossary.md#errors-model), [Проверяемые исключения](glossary.md#errors-checked-exceptions), [Диагностика неиспользованного результата](glossary.md#errors-must-use)

**Ответ.** Checked exception требует catch/throws для исключительного канала. Result передаёт ошибку обычным значением. Must-use диагностирует некоторые случаи отбрасывания, но не доказывает корректную обработку.

**Основания и пример.** Java checked exceptions противопоставлены Rust Result и явному let _ = operation().

**Предел текущей модели.** Флаг severity зависит от инструментального профиля; общий тип ошибки не описывает политику всего проекта.

**Для реализации языка.** Проверять потоки исключений, возвращаемый тип и предупреждения о неиспользовании как разные задачи.

## Сборщик мусора гарантирует закрытие файла? { #q07 }

**Понятия:** [Освобождение памяти](glossary.md#memory-management), [Освобождение ресурсов](glossary.md#resources-cleanup), [Представление и передача ошибок](glossary.md#errors-model)

**Ответ.** Нет. GC отвечает за память; закрытие ресурса имеет собственный протокол. RAII, with и try-with-resources задают явные правила очистки на определённых путях выхода.

**Основания и пример.** Карточки C++, Rust, Python и Java содержат отдельные механизмы памяти и ресурсов.

**Предел текущей модели.** Для утверждения о гарантии нужно назвать аварийные выходы, отмену и прекращение процесса; все эти пути ещё не формализованы в схеме.

**Для реализации языка.** При lowering учесть очистку при return и исключительном выходе, а не только при конце текста блока.

## Замыкание и продолжение сохраняют одно и то же? { #q08 }

**Понятия:** [Захват окружения](glossary.md#subprograms-closures), [Правило разрешения имён](glossary.md#scope-resolution), [Граница захвата продолжения](glossary.md#control-continuation-extent), [Протокол выдачи и возобновления результатов](glossary.md#evaluation-result-protocol)

**Ответ.** Нет. Замыкание сохраняет доступ к окружению функции; продолжение представляет оставшийся контекст вычисления. Продолжение Scheme можно вызвать повторно, но изменения памяти при этом не откатываются.

**Основания и пример.** Пример Scheme continuation.scm действительно выдаёт 11, 12, 13.

**Предел текущей модели.** One-shot/multi-shot и срок допустимости продолжения пока описываются текстом, а не отдельными значениями онтологии.

**Для реализации языка.** Разделить представление environment и continuation; захваченный контекст управления не обязан быть обычным кадром стека.

## Генератор делает язык нестрогим? { #q09 }

**Понятия:** [Стратегия вычисления](glossary.md#evaluation-strategy), [Протокол выдачи и возобновления результатов](glossary.md#evaluation-result-protocol), [Логический поиск решений](glossary.md#control-logic-search)

**Ответ.** Нет. Python yield приостанавливает определённое вычисление, не меняя строгую передачу обычных аргументов. Icon дополнительно возобновляет поиск из-за failure внешнего выражения.

**Основания и пример.** Пример Icon различает find внутри сравнения и уже сохранённое первое значение.

**Предел текущей модели.** Порядок вычисления операндов и стратегия востребованности ещё не разделены на полностью заполненные оси для всех языков.

**Для реализации языка.** Определить события resume и failure и состояние, сохраняемое между ними, отдельно от evaluation order вызова.

## Перегрузка, type class и виртуальный вызов — один механизм? { #q10 }

**Понятия:** [Перегрузка по сигнатуре](glossary.md#subprograms-overloading), [Параметрический полиморфизм](glossary.md#subprograms-generics), [Диспетчеризация вызовов](glossary.md#abstraction-dispatch), [Контракты полиморфизма](glossary.md#abstraction-contracts)

**Ответ.** Нет. Java выбирает перегрузку статически, затем может динамически выбрать переопределённый метод. Haskell type class задаёт ограничения операций; CLOS multiple dispatch выбирает методы по нескольким аргументам.

**Основания и пример.** Карточки Java, Haskell и Common Lisp содержат разные описания механизмов.

**Предел текущей модели.** Coherence, приоритет специализаций и порядок комбинации методов пока не представлены отдельными полями.

**Для реализации языка.** Не смешивать разрешение имени, выбор сигнатуры, передачу словаря операций и runtime dispatch.

## Сопоставление с образцом — это унификация? { #q11 }

**Понятия:** [Сопоставление с образцом](glossary.md#control-pattern-matching), [Формы присваивания и связывания](glossary.md#bindings-assignment), [Режимы связанности аргументов](glossary.md#computation-instantiation-modes), [Логический поиск решений](glossary.md#control-logic-search)

**Ответ.** Не в общем случае. Pattern matching проверяет форму значения и извлекает части. Унификация согласует два терма с переменными с обеих сторон. В Prolog X=1, X=2 приводит к неудаче, а не к обновлению X до 2.

**Основания и пример.** Карточки Prolog, Rust и Haskell позволяют сравнить направленное сопоставление с унификацией.

**Предел текущей модели.** Occurs-check, rational trees и ограничения образцов требуют уточнения выбранного Prolog-профиля.

**Для реализации языка.** Развести проверку конструктора/извлечение полей и алгоритм связывания логических переменных с откатом.

## det означает, что функция обязательно завершится? { #q12 }

**Понятия:** [Режимы связанности аргументов](glossary.md#computation-instantiation-modes), [Объявленная кратность решений](glossary.md#computation-solution-cardinality), [Режим гарантии тотальности](glossary.md#verification-totality)

**Ответ.** Нет. Mercury det утверждает одно решение для возвращающихся вызовов указанного режима. Проверка termination/productivity — отдельное обязательство.

**Основания и пример.** Документация Mercury явно оговаривает returning calls; пример append имеет det и multi режимы.

**Предел текущей модели.** Карточки Mercury пока нет; эксперимент подготовлен, но ещё не запускался. Заполненная ось словаря не является подтверждённым запуском.

**Для реализации языка.** Отдельно анализировать число решений, связанность аргументов, покрытие образцов и завершение.

## Почему одинаковая операция даёт разные результаты для коллекций? { #q13 }

**Понятия:** [Кратность элементов коллекции](glossary.md#data-collection-multiplicity), [Поднятие операций по рангу массива](glossary.md#evaluation-rank-lifting), [Формы итерации](glossary.md#control-iteration)

**Ответ.** Нужно знать кратность, порядок и выбранную ячейку массива. SQL DISTINCT убирает дубликаты; rank в J меняет, к каким частям матрицы применяется операция. Это независимые решения.

**Основания и пример.** SQL запущен на SQLite; для J подготовлены ожидаемые 6 15 и 5 7 9, но запуска ещё нет.

**Предел текущей модели.** Shape, порядок и SQL three-valued truth domain пока не полностью выделены в самостоятельные концепции.

**Для реализации языка.** Зафиксировать тип коллекции и правила поднятия операций до выбора реализации циклом или векторной инструкцией.

## Синхронный канал и синхронные такты означают одно и то же? { #q14 }

**Понятия:** [Синхронизация отправки и приёма](glossary.md#resources-communication-coupling), [Выбор сообщения из очереди](glossary.md#resources-receive-selection), [Временная область модели](glossary.md#computation-time-domain), [Ожидание доступности данных](glossary.md#evaluation-data-availability)

**Ответ.** Нет. Рандеву согласует отправителя и получателя; логические такты индексируют значения реактивной программы. Selective receive выбирает сообщение, а dataflow suspension ждёт информацию.

**Основания и пример.** Карта сопоставляет occam, Erlang, Lustre и Oz; трасса Lustre рассчитана вручную.

**Предел текущей модели.** Fairness, deadlines и устойчивость к сбоям не следуют из этих меток и требуют отдельных утверждений.

**Для реализации языка.** Определить модель ожидания, очередь событий и модельное время независимо от реального планировщика потоков.

## Как отличить присваивание, уравнение и отложенное обновление? { #q15 }

**Понятия:** [Формы присваивания и связывания](glossary.md#bindings-assignment), [Направленность уравнений и присваиваний](glossary.md#computation-equation-causality), [Планирование обновлений в HDL-симуляции](glossary.md#computation-update-scheduling), [Временная область модели](glossary.md#computation-time-domain)

**Ответ.** Присваивание обновляет цель; уравнение Modelica задаёт отношение для совместного решения; Verilog nonblocking assignment планирует применение уже вычисленной правой части. Похожий знак не задаёт единую семантику.

**Основания и пример.** Verilog swap запущен и различает active/settled; Modelica Ohm пока проверена ручным расчётом.

**Предел текущей модели.** Полные IEEE event regions и разрешимость общих систем уравнений не описаны текущим минимальным примером.

**Для реализации языка.** Для этих случаев нужны разные IR: последовательные обновления, система отношений или события отложенных записей.
