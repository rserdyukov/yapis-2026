# fsmc — компилятор языка конечных автоматов FSM в WebAssembly

Учебный пример к лабораторному практикуму ЯПИС. Задача взята из карточки
«Диалог банкомата» (домен «Конечные автоматы и протоколы»). Описание для
студентов лежит на сайте курса: [Пример компилятора: FSM → WASM](https://rserdyukov.github.io/yapis-2026/labs/fsm-compiler/).
Там же есть [playground](https://rserdyukov.github.io/yapis-2026/playground/),
где этот компилятор работает в браузере через Pyodide.

```bash
pip install -r requirements.txt           # antlr4-python3-runtime, lark
./compile.sh examples/atm.fsm scenarios/01_success.events
python3 -m unittest discover -s tests -v  # нужны node и wat2wasm, иначе часть тестов — SKIP
```

## Структура

| Путь | Что |
|---|---|
| `grammar/Fsm.g4` | грамматика ANTLR 4 |
| `fsmc/frontend_antlr/` | ANTLR-фронтенд: `ErrorListener` и `Visitor` → AST; `generated/` — сгенерированный парсер (коммитится) |
| `fsmc/frontend_lark/` | Lark-фронтенд: `fsm.lark` (LALR(1)) и `Transformer` → AST |
| `fsmc/ast.py` | AST, общее для обоих фронтендов |
| `fsmc/semantic.py` | таблицы символов, типы, анализ графа переходов |
| `fsmc/codegen.py` | модель → инструкции WebAssembly |
| `fsmc/wasm.py` | печать инструкций в WAT и двоичный `.wasm` |
| `fsmc/diagram.py` | диаграмма Mermaid |
| `fsmc/web.py` | JSON-мост для playground |
| `runtime/fsm-host.mjs` | хост для Node и браузера; `run.mjs` — запуск сценария в Node |
| `reference/reference.py` | эталон из карточки: оракул для дифференциальных тестов |
| `examples/` | `atm.fsm` — банкомат; `features.fsm` — все конструкции языка |
| `scenarios/` | сценарии событий для банкомата |
| `tests/negative/` | программы, которые не должны компилироваться; `// expect:` — точный набор кодов |
| `tools/gen_antlr.py` | перегенерировать парсер после правки `Fsm.g4` (`--check` — проверить актуальность) |

Два фронтенда нужны, чтобы показать: ANTLR — не единственный способ.
Грамматика, алгоритм разбора и способ построения AST у них разные
(ALL(\*) и Visitor против LALR(1) и Transformer), а результат одинаковый. Выбор
задаётся флагом `--frontend antlr|lark` или переменной `FSMC_FRONTEND`
для `compile.sh`.

## Семантические проверки

| Код | Уровень | Проверка |
|---|---|---|
| E001 | ошибка | лексическая ошибка |
| E002 | ошибка | синтаксическая ошибка |
| E101 | ошибка | состояние не объявлено (с подсказкой ближайшего имени) |
| E102 | ошибка | состояние недостижимо из начального |
| E103 | ошибка | из состояния нет пути в терминальное |
| E104 | ошибка | событие не объявлено |
| E105 | ошибка | арность или тип образца события не совпадает с объявлением |
| E106 | ошибка | два перехода по одному событию без guard'а |
| W107 | предупреждение | несколько guard'ов без явного порядка `else` |
| W108 | предупреждение | событие не обработано в состоянии и не объявлено `ignore` |
| E109 | ошибка | действие не объявлено |
| E110 | ошибка | имя в выражении не существует |
| E111 | ошибка | guard не `bool` |
| E112 | ошибка | нет начального или терминального состояния, начальных больше одного |
| E113 | ошибка | повторное объявление; имя образца совпадает с полем или константой |
| E114 | ошибка | арность или типы аргументов действия |
| E115 | ошибка | типы: неизвестный тип, несовместимые операнды, присваивание константе или параметру |
| E116 | ошибка | у перехода `a \| b` образцы событий связывают разные имена |
| W117 | предупреждение | переход никогда не сработает: выше стоит переход без guard'а |
| W118 | предупреждение | у всех переходов события есть guard'ы, нет `else` |
| W120 | предупреждение | действие нигде не вызывается |

E101–E112 — это строки 1–12 таблицы из раздела 5 карточки задачи.

## Метрики для отчёта (раздел 7 карточки)

| Ошибка `naive.py` | В Python | В FSM | Строк компилятора |
| --- | --- | --- | ---: |
| Опечатка в состоянии | не обнаружена никогда | E101 | 13 |
| Недостижимое состояние | не обнаружена никогда | E102 | 31 |
| Необработанный `timeout` | не обнаружена никогда | W108 | 6 |
| Граница числа попыток | тест, если о нём догадались | остаётся тестом (`scenarios/02`) | — |

Считались непустые строки без комментариев в `fsmc/semantic.py`. Для E102
учтены построение графа (`edges`), обход в ширину (`_bfs`) и цикл проверки.
Для E101 — `_state_ref` и подсказка имени.

## Генерация кода

См. строку документации в `fsmc/codegen.py`. Коротко:

- состояние — `global $state`, поля контекста — `global $ctx_*`;
- событие — экспорт `on_<имя>`, который выбирает ветку через `br_table`;
- строки — `[длина][UTF-8]` в линейной памяти, `$str_eq` и `$alloc` на WAT;
- описание машины — JSON в пользовательской секции `fsm.meta`.

Тест `test_encoder_matches_wat2wasm` собирает наш WAT утилитой `wat2wasm` и
требует побайтного совпадения с нашим кодировщиком (без секции `fsm.meta`).
