# grammar-lab — самопроверка практической задачи 3 (LL(1))

Студент записывает решение [задачи 3](https://rserdyukov.github.io/yapis-2026/practice/task3/)
на маленьком формальном языке. Программа проверяет каждый шаг и объясняет
ошибки. Код общий для страницы сайта (Pyodide), командной строки и тестов.

Проектный документ: `2026-09-26-task3-selfcheck-kickoff.md` в рабочих
материалах курса (`YaPIS/output/design/`; в репозитории сайта не хранится).

> **Статус:** DSL v1 утверждён; проверка шагов 4–6 (FIRST, FOLLOW, таблица,
> конфликты, трассы) и редактор с подсветкой и таблицами внутри текста реализованы. Сравнение грамматики с
> описанием языка варианта — следующий инкремент.

```bash
pip install -r requirements.txt
python3 -m grammarlab check tests/fixtures/v08-ok.txt   # 0 — ошибок нет, 1 — есть, 2 — не разобрано
python3 -m grammarlab check ответ.txt --level 2         # только «где», без «почему»
python3 -m grammarlab check ответ.txt --reveal          # плюс эталон ошибочных элементов
python3 -m unittest discover -s tests -v
```

## 1. Язык ответа (DSL v1)

Ответ — обычный текст, разбитый на секции. Секция начинается заголовком
в отдельной строке и продолжается до следующего заголовка. Секции можно
пропускать: проверяется только то, что записано. Порядок секций свободный,
но каждая из `grammar`, `first`, `follow`, `table` встречается не больше
одного раза.

```text
version: 1          # необязательно; комментарий начинается с # и идёт до конца строки

grammar:            # шаг 1/3: грамматика, для которой строится анализатор
first:              # шаг 4: FIRST нетерминалов
follow:             # шаг 4: FOLLOW нетерминалов
table:              # шаг 5: таблица предиктивного анализатора M
conflicts:          # шаг 2: объявленные конфликты (только для не-LL(1) вариантов)
trace "h t i b ;":  # шаг 6: трасса разбора строки; секций trace может быть несколько
```

### 1.1. Символы

Символы разделяются **пробелами**: `N -> t i N`, а не `N -> tiN`.

| Запись | Что это |
|---|---|
| `P`, `H`, `Expr`, `E'`, `E1` | имя: буквы, цифры, `_` и `'`; начинается с буквы |
| `'<>'`, `','`, `'|'`, `'->'` | терминал в одинарных кавычках — **обязательно** для пунктуации и служебных знаков DSL |
| `if`, `t`, `i` | имя без кавычек — терминал, если не встречается слева от `->` |
| `eps` или `ε` | пустая цепочка |
| `$` | конец входа (только в `follow`, `table`, `trace`) |

**Нетерминалы** — это ровно те имена, которые стоят слева от `->` в секции
`grammar`. Стартовый символ — левая часть первого правила. Любое другое
имя — терминал.

Пунктуация без кавычек (`,` `;` `(` `)` `<>` и т.п.) — ошибка разбора
с подсказкой «возьмите терминал в кавычки». Так нельзя спутать терминал
`'|'` с разделителем альтернатив.

Перед проверкой программа показывает, как она поняла ответ: например,
если написано `N -> tiN`, в интерпретации будет видно, что `tiN` — один
неизвестный терминал, и появится предупреждение.

### 1.2. `grammar:`

```text
grammar:
  P -> H G
  G -> B G | eps
  H -> h N
  N -> t i N | eps
  B -> b M ';'
  M -> ',' b M | eps
```

- одна строка — один нетерминал; альтернативы через `|`;
- нетерминал может повторяться в нескольких строках — альтернативы объединяются;
- стрелка: `->` или `→`.

### 1.3. `first:` и `follow:`

```text
first:
  P = { h }
  N = { t, eps }
  M = { ',', eps }

follow:
  P = { $ }
  N = { b, $ }
  M = { ';' }
```

- элементы через запятую; запятая внутри кавычек — терминал `','`;
- пустое множество — `{ }`;
- порядок элементов и строк не важен.

### 1.4. `table:`

Одна строка — одна непустая ячейка:

```text
table:
  M[P, h] = P -> H G
  M[N, t] = N -> t i N
  M[N, b] = N -> eps
  M[N, $] = N -> eps
```

- ячейки, которых нет в списке, считаются пустыми (ошибка);
- конфликт — несколько правил через `;;`:
  `M[X, else] = X -> else O ;; X -> eps` (разделитель выбран так, чтобы не
  совпадать ни с `|`, ни с терминалом `';'`);
- `M[N, t]` — индекс строки таблицы: нетерминал и терминал (или `$`).

### 1.5. `conflicts:` (шаг 2, только если таблица не LL(1))

```text
conflicts:
  M[X, else]: if i then if i then o else o     # строка с двумя деревьями разбора
  choose M[X, else] = X -> else O             # как разрешён конфликт (else — к ближайшему if)
```

Объявлять конфликт нужно только у вариантов 18, 28, 29 (висячий else).
У остальных вариантов конфликт означает, что шаг 3 (преобразование) не доделан.

### 1.6. `trace "<строка>":`

Строка во входе записывается терминалами через пробел, `$` дописывается
автоматически. Каждая строка трассы — три колонки через `|`:
стек (вершина слева), остаток входа, действие.

```text
trace "h t i b ;":
  P $            | h t i b ';' $ | P -> H G
  H G $          | h t i b ';' $ | H -> h N
  h N G $        | h t i b ';' $ | match h
  N G $          | t i b ';' $   | N -> t i N
  t i N G $      | t i b ';' $   | match t
  i N G $        | i b ';' $     | match i
  N G $          | b ';' $       | N -> eps
  G $            | b ';' $       | G -> B G
  B G $          | b ';' $       | B -> b M ';'
  b M ';' G $    | b ';' $       | match b
  M ';' G $      | ';' $         | M -> eps
  ';' G $        | ';' $         | match ';'
  G $            | $             | G -> eps
  $              | $             | accept
```

- действия: `A -> α` (применить правило), `match x`, `accept`, `error`;
- символы в колонках пишутся так же, как в грамматике (пунктуация — в кавычках);
  разделитель колонок — `|`;
- в заголовке `trace "…"` строка пишется как есть, терминалы через пробел;
- неправильная строка заканчивается строкой с действием `error`;
- правильная строка — строкой `$ | $ | accept`.

Порядок: одна правильная строка и две неправильные (условие, п. 6).

## 2. Как проверяется

Все эталоны вычисляются **из грамматики студента** (секция `grammar`):

| Шаг | Проверка | Подсказка уровня 3 |
|---|---|---|
| разбор | синтаксис DSL; неизвестные символы; непродуктивные и недостижимые нетерминалы | — |
| FIRST/FOLLOW | сравнение множеств | недостающий элемент — вывод, показывающий, почему он там есть (`P ⇒ H G ⇒ … ⇒ h N b M ; G`); лишний — объяснение по правилам |
| таблица | сравнение ячеек; конфликты | строка входа, на которой трасса по вашей таблице расходится с правильной, и первый различающийся шаг |
| конфликты | объявлен ли каждый конфликт, есть ли у свидетеля два дерева | — |
| трассы | симуляция по **вашей** таблице; первая неверная строка; принадлежность строки языку | ожидаемая строка трассы |

Уровни подсказок: 1 — «в шаге 4 две ошибки»; 2 — где (какое множество, ячейка,
строка трассы); 3 — почему. Кнопка «показать эталон» раскрывает правильный
элемент. Защиты от перебора нет — это самопроверка.

Итог до появления проверки языка (инкремент 3): «алгоритм применён верно;
соответствие грамматики описанию языка не проверялось».

## 3. Редактор на странице

Ответ набирается в редакторе CodeMirror 6 (`docs/practice/task3-check/editor.mjs`):

- **подсветка** языка ответа (заголовки секций, нетерминалы, терминалы,
  `eps`, `->`, комментарии);
- **ошибки разбора** подчёркиваются прямо в тексте и отмечаются на полях — это
  та же диагностика, что у `python -m grammarlab check` (коды `S…`, `W…`),
  через паузу после набора;
- **автодополнение** нетерминалов, терминалов и заголовков секций (Ctrl+Space);
- **таблицы внутри текста**: разобранные секции `first`, `follow`, `table` и
  трассы показываются таблицами на месте своего текста. Отметка в таблице
  переписывает текст секции; Ctrl+Z отменяет её как любую правку. Курсор,
  поставленный в секцию (стрелками или кликом по номеру строки), и кнопка
  «текст» показывают исходный текст. Секция с ошибкой разбора или с записями,
  которых таблица не выразит (символ не из грамматики и т. п.), остаётся текстом.

Текст — единственный источник правды: разбор, границы секций и модель таблиц
строит Python (`grid.layout`), текст секции из таблицы собирает `render.mjs`
по меткам из той же модели (совпадение с `grid.apply_grid` проверяет smoke-тест).
Проверка всегда читает текст.

CodeMirror собран в один файл `docs/practice/task3-check/codemirror.mjs`
(117 КБ gzip) из версий, закреплённых в `tools/codemirror-bundle/package-lock.json`:

```bash
cd tools/codemirror-bundle && npm ci && node build.mjs          # пересобрать
node build.mjs --check                                          # CI: бандл актуален
```
